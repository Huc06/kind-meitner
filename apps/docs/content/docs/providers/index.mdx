Agent engines are local runtime. They start a CLI on this computer. They are not the OKX catalog. [Invite an OKX agent](/docs/okx/agents) from a room first. Use an engine when a local bot has to run Claude, Codex, or another CLI.


<ProductScreenshot name="docs-engine-detection" alt="kind-meitner checking which agent engines are installed" caption="The official app checks installation and sign-in state without asking users to find executable paths first." />

## Built-in engines

| Engine | Authentication shape | Notes |
|---|---|---|
| Claude | Claude CLI login | Strong support for tools, approvals, sessions, and local computer use |
| Grok | Grok CLI login, or an xAI API key | ACP-based local model catalog and session support. The API-key driver is available when an instance is configured; the default fleet uses the CLI |

Additional driver instances can be declared in local configuration. Unavailable engines remain visible with a reason instead of crashing the provider fleet.

## Detection

kind-meitner checks common installation directories and the login shell in the background. Restart the app after installing or authenticating a CLI.

If detection fails, use **Settings → Engines** to set an explicit executable path. This is supported for every engine and is the most reliable solution for version managers, wrappers, custom builds, and Windows installations outside the normal path.

## Model selection

The model picker groups models by provider and marks defaults. Supported engines can refresh their model catalog from the installed CLI. Changing the model affects future turns; it does not rewrite earlier transcript history.

## Multiple Claude accounts

Open **Settings → Engines → Add Claude account** and give the account a name, such as **Work** or **Personal**. kind-meitner creates a separate configuration-directory setting for it; it does not copy your existing login. Under **Manage account and sign-in**, copy the sign-in command and run it on the computer hosting kind-meitner, then choose **Check account**. On Windows, use PowerShell. Claude handles the browser sign-in and stores its own credentials.

In a bot's model picker, choose **Claude**, select **Work** or **Personal** in the **Account** dropdown, then choose a model to save the selection. Claude appears only once in the provider list. Each bot keeps its own selection, and the chat header shows the account name. Account changes apply to future turns and are blocked while that bot is responding; other bots are unaffected. Conversation history is not erased when you change the selection.

The original **Default** entry keeps using your existing CLI login. Advanced users can supply an existing, separate Claude configuration directory. Once an account has been used by bots or conversation history, add a new account instead of repointing its directory. Removing an account from kind-meitner does not delete its files or sign it out; first move any bots using it to another account.

This does not require a CLI proxy, and there is no automatic account rotation or fallback. Named account management currently supports Claude only.

<Callout type="info" title="Subscriptions stay with the provider">
  Your existing CLI login or provider API key determines access and billing. kind-meitner does not turn one subscription into access to another provider.
</Callout>
